## 这份文件是什么

**它是随仓库版本化的能力文档，不是技能指令。** WorkBuddy / Claude Code 加载本技能时只读取 `SKILL.md` 及其引用的 `lib/`、`sites/`、`references/`；`docs/` 里的报告不会被注入会话上下文，因此不会增加每轮对话成本。GitHub Pages 从 `main:/docs` 发布，把 `index.html` 渲染成在线页面。

产物与技能本体分离：抓取数据留在工作区，不进仓库；`EXPERIENCE.md` / `TODO.md` / `sites/` 分册才是会被 agent 读取的记忆层。

## 三、评论采集能力（2026-11-14 打通）

| 结论 | 依据 |
|---|---|
| **能抓到** | 话题卡片无链接、不显示真实评论数（卡片上的数字是点赞数）；但 RSC 帖对象带 `cmts`（真实评论数）与 `id/egid`，可直接拼 `gossip-detail` 详情页，拦截 `comments.lst` 拿结构化评论 |
| **能与帖子正确关联** | 按帖 ID 建详情页 URL，评论与正文一一对应；公司印象 62.2% 的帖有评论、职言 78.8% |
| **能按公司定向** | RSC 的 `title` 才是「评价对象公司名」（如「中兴通讯印象 · 能源 · 3年以上」），此前被 `collectPosts` 丢弃；项目侧 `collectPostsRich` 已补齐 |
| **覆盖率** | 首屏约 28%，加入循环展开到收敛后 **88.1%**（全量一轮） |

**全量一轮结果**：帖子池 802 帖（目标公司命中 10 帖），实抓 139 帖；声明 4,171 条评论 → 抓到 3,673 → 清洗后有效 **3,045**（82.9%）。清洗剔除广告 153 / 无效 119 / 求职搭话 284 / 重复 72。

**按公司样本充足度**（对齐「<10 条不得给 A」）：

| 公司 | 帖子 | 有效评论 | 判定 |
|---|---|---|---|
| 深圳联友科技 | 1 | 5 | thin |
| 明略科技 | 1 | 2 | insufficient |
| 贝壳找房 | 6 | 58 | ok |
| 沃尔玛中国 | 1 | 10 | ok |
| 瑞幸咖啡 | 1 | 2 | insufficient |

评论的价值是**增量信息**：例如「贝壳财务当年一年流动二十人、晚上干到八九点、月初熬到十二点、大量裁员」这类正文里完全没有的细节。但「没有评价」只能记样本不足，不能当好评。
