# 站点抓取规则（按媒体分册）

> 用途：执行 `/web-analysis-ai` 采集前，**先读对应站点分册**，按其中的规则和方法执行；
> 没有分册的站点 → 走「探索模式」，跑通后**必须**回来新建分册并记录。
>
> 建立于 2026-11-10。分册规则借鉴 agent-reach 的通用原则（终止信号语义、节流、会话复用）。

---

## 使用流程（每次采集前必做）

1. **查分册**：`sites/<host>.md` 是否存在。
2. **有分册** → 按「连接方式 / 登录 / 节流参数 / 风控信号 / 已知坑」逐条执行，不要临场发挥。
3. **无分册** → 探索模式：
   - 用小批量（≤10 条）试通，记录真实交互方式与选择器；
   - 遇到任何坑（风控、结构变化、字段取不到），当场记录进本分册；
   - 跑通后**立即**创建 `sites/<host>.md`，把探索结论写全。
4. **分册与实测冲突** → 以**实测为准**，并回头修正分册（不要让旧文档误导下一次）。

## 硬性原则（所有站点通用）

### 1. 风控是终止信号，不是重试信号

遇到以下任一情况，**立即停止本次采集**，报告用户，不重试、不换账号、不换后端：

- 页面跳转到验证码 / 登录墙
- 接口返回风控状态码（各站不同，见分册）
- 内容突然全空，但登录态看起来正常

理由：风控基于账号+设备+IP 的历史行为累积，重试只会加深标记。

### 2. 有头模式是默认，不是选项

headless Chrome 缺 GPU 渲染、`navigator.webdriver` 为 true、窗口尺寸异常，是多数站点的**直接风控触发器**。

统一用 `lib/headed.js` 的 `launchHeaded()`：有头 + 窗口在屏幕内 + 立即置底（不抢焦点、不遮挡用户窗口）。

窗口标题 `Google Chrome for Testing` 与用户主浏览器 `Google Chrome` 区分，置底不会误伤。

### 3. 节流参数必须显式配置

不依赖脚本里的硬编码 sleep。每个站点分册必须写明：

- 搜索请求间隔
- 详情页请求间隔
- 单次任务最大条数

参考基线（来自 agent-reach）：同平台两次搜索 ≥10 秒；同平台并发 ≤2；全平台并发 ≤4。

### 4. 登录态：优先持久化 profile，不复制 cookie

Chrome 127+ 启用 App-Bound Encryption，外部程序读 `Cookies` 库只能拿到密文。

- **正确**：`launchPersistentContext(profiles/<host>)`，登录态独立保存，长期复用。
- **错误**：从主 Chrome 复制 cookie 文件（技术上不可行）。
- **单会话站点**（新登录踢掉旧会话）：用 `cdpUrl` 挂载用户已登录的主 Chrome，不产生新登录事件。

### 5. 被抓数与站点自报数都要写

站点自报的总数常虚高（牛客自报 703，实际 total 113）。报告里两个数都写，注明哪个是实得。

## 渠道选择决策树

```
要什么数据？
├─ 薪资数字（可信）      → 脉脉薪资话题（员工自报，最准）
├─ 上下班时间            → 脉脉工时话题（唯一有具体时间）
├─ 公司是否在收缩        → 职友集招聘趋势（招聘端事实）
├─ 校招/面试体验         → 牛客（校招主战场）
├─ 负面爆料/裁员消息     → 脉脉爆料 + 小红书
├─ 业务线级评价          → 三渠道都做不到（只有公司级）
└─ 消费投诉/产品口碑     → 小红书
```

**关键认知**：没有任何一个渠道提供**部门级**数据。所有渠道都是公司级。
要拿业务线差异，只能靠关键词过滤（如「携程金融」）或人工访谈。
