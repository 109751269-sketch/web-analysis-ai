# 职友集 jobui.com 抓取分册

> 风控等级：**中**（搜索有验证码，公司页无风控）
> 最后实测：2026-11-10

---

## 一、连接方式

**纯 HTTP GET，无需登录、无需浏览器、无需 cookie。**

这是本技能里最省事的一站。不要用 Playwright，不要开有头窗口。

```js
const HEADERS = {
  'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/157.0.0.0 Safari/537.36',
  'Accept': 'text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8',
  'Accept-Language': 'zh-CN,zh;q=0.9',
  'Referer': 'https://www.jobui.com/',
};
```

缺 `Referer` 或 `Accept-Language` 会更容易触发搜索验证码。

### 两个入口，风控完全不同

| 入口 | URL | 风控 | 用途 |
|---|---|---|---|
| **搜索** | `/cmp?keyword=<公司名>` | ⚠️ 有验证码 | **只用来定位公司 ID，用完即弃** |
| **公司页** | `/company/<id>/` | ✅ 无 | 主数据来源，可无限取 |
| 薪资页 | `/company/<id>/salary/` | ✅ 无 | 历年工资变化 |
| 职位页 | `/company/<id>/jobs/` | ✅ 无 | 在招岗位、学历/经验分布 |

**核心策略：搜索 ID 一次，永久缓存**（`output/jobui/_ids.json`）。之后只走公司页，再也不碰搜索。

## 二、风控参数

| 参数 | 值 | 说明 |
|---|---|---|
| 搜索间隔 | **≥20s**（实测 2 次连发即触发）| 保守值 25s |
| 公司页间隔 | 2.5s | 无风控，可更快，但不必激进 |
| 风控后冷却 | 40-60s 可恢复 | 不是永久封禁，是临时限流 |
| 单次任务上限 | 搜索 ≤6 次/批 | 超过容易连续触发 |

### 风控信号

返回的 HTML 是验证码页，**HTTP 状态码仍是 200**，必须检查正文：

```js
const RISK = {
  captchaTitle: /验证码验证|系统检测到访问异常/,
  captchaBody: /请输入下方验证码/,
};
```

页面特征：`<title>验证码验证</title>`、`系统检测到访问异常`、`为保障账户安全，请输入下方验证码完成验证`、`valid.php` 表单、图片验证码（非滑块）。

**只能人工输入**，没有自动过验证码路径。所以策略是**根本不要走到风控**——靠缓存 ID 规避。

## 三、可用维度

职友集的独特价值：**它给的是招聘端的事实，不是员工自报。** 这填补了其他三站的盲区。

| 维度 | 字段 | 数据来源 | 独特价值 |
|---|---|---|---|
| **招聘趋势** | `hiringTrend.dir/pct/series` | 历年在线职位数 | 判断**稳定性**：招聘骤降 = 收缩信号 |
| **薪酬区间** | `salary.mainRange/band` | 平台发布岗位薪资 | 交叉验证脉脉自报薪资是否可信 |
| **历年工资** | `history.series` | 逐年平均工资 | 判断薪资是涨是跌 |
| **学历工资** | `salary.byEducation` | 本科/硕士/博士 | 学历溢价 |
| **城市工资** | `salary.byCity` | 上海/北京/深圳… | 地域差异 |
| **人才结构** | `requirement.topEducation/topExperience` | 学历/经验分布 | 岗位门槛 |
| **行业地位** | `rankings`、荣誉 | 人气排名 | 冷启动难度 |

### 岗位细分（最有价值的能力）

`/company/<id>/salary/j/<岗位拼音>/` 给出**单个岗位**的薪资画像，这是职友集独有、其他三站都没有的。

实测携程「投放」岗（`/salary/j/toufang/`）：

```
薪酬区间 3K-50K，91.7% 的岗位拿 20-50K，样本 24 个
按经验：应届 3.8K / 1-3年 25.0K / 3-5年 32.5K
按学历：本科 29,479
按城市：上海 29.4K（87.5%，21 个岗位）
对比：上海投放平均 23,355 | 上海互联网行业投放平均 26,231
```

**这个「与同地区比 +12%」的对比数据是独有的**——它直接告诉你这个岗位在当地市场的相对位置。

常用岗位路径：`java` `suanfa` `qianduan` `houduan` `chanpinjingli` `analyst` `toufang` `yunying` `fawu` `fengkong` `hr` `kefu`

### 为什么不能只用公司级平均工资

实测教训：美团平均工资 16.1K、滴滴 18.3K，看起来「很低」，但这是**骑手/客服岗位大量招聘拉低均值**的结果，不代表技术岗。

**公司级平均薪资在职友集上是招聘结构指标，不是薪酬水平指标。** 要判断技术岗薪酬，必须走 `/salary/j/<岗位>/`。

脉脉的员工自报薪资没有这个问题（发帖人多是技术/产品岗），所以：
- 脉脉薪资 = 真实薪酬水平（用于排名）
- 职友集公司级薪资 = 招聘结构（技术岗占比）
- 职友集岗位薪资 = 具体岗位的市场位置

### 不能拿的

- ❌ **员工点评正文**：`/review/` 需要登录，且 2128 条点评多为工资晒单，无实质内容
- ❌ **部门级数据**：同脉脉一样只有公司级
- ❌ **在职体验**：职友集是招聘网站视角，没有「这家公司待着爽不爽」

## 四、已知坑

### 坑 1：搜索结果第一页混入大量同名子公司

搜「腾讯」第一条是「腾讯科技（上海）有限公司」，不是主体「深圳市腾讯计算机系统有限公司」。

**原因**：职友集按人气排序，但子公司可能因为近期发布大量职位而人气虚高。

**对策**：过滤子品牌关键词。

```js
const SUB = /音乐|云计算|云科技|金融|支付|影业|视频|地图|物流|医疗|健康|教育|出行|文化|体育|（.*?）|\(.*?\)/;
function pickBest(list, kw) {
  const hit = list.filter(c => c.name.includes(kw));
  const pool = hit.length ? hit : list;
  return pool.find(c => !SUB.test(c.name)) || pool[0];
}
```

注意：括号会误伤「携程计算机技术（上海）有限公司」这类主体名。对携程直接写死 ID `12078481`。

### 坑 2：搜索结果解析 —— 不是标准列表

没有 `<ul><li>` 结构。要按块切：

```js
const blocks = html.split('class="company-logo-link ').slice(1);
for (const b of blocks) {
  const id = (b.match(/data-companyID="(\d+)"/) || [])[1];
  const name = (b.match(/alt="([^"]+) logo"/) || [])[1];
}
```

### 坑 3：公司名带「logo」后缀

`alt="深圳市腾讯计算机系统有限公司 logo"`。取名要去掉，且用 `alt` 不用 `<h3>`——`<h3>` 里含 `<span>` 高亮标签，会切碎关键词。

### 坑 4：`/review/` 返回 301

必须 `redirect: 'follow'`。但跳转后仍需要登录才有内容，实际不可用。

### 坑 5：招聘趋势的两个字段要分开抓

- 同比：`招聘：2026年较2025年下降14%`（在公司主页顶部简介区）
- 绝对数：`携程历年招聘：2021年 2051个 2022年 2576个 …`（在「招聘需求增长速度」区块）

只抓同比会丢掉「基数」。腾讯 2026 年招聘下降 58%，但仍有 553 个在线职位——单看 -58% 会误判为崩塌。

### 坑 6：数字带千分位和单位

`199.5万` / `2128` / `￥36.3K`。解析时要处理 `万` 和 `K`。

## 五、用法

```bash
# 1. 解析公司 ID（慢，每家 25s，只跑一次）
node jobui_resolve_ids.js

# 2. 批量采集（读缓存 ID，只走公司页）
node jobui_collect.js

# 3. 单家重采
node jobui_collect.js 腾讯
```

输出：`output/jobui/<公司名>.json` + `_all.json` + `_ids.json`（ID 缓存）

## 六、与其他渠道的关系

| | 脉脉 | 牛客 | 小红书 | **职友集** |
|---|---|---|---|---|
| 视角 | 在职员工吐槽 | 校招/面试 | 消费者+员工混合 | **招聘端** |
| 优势 | 薪资工时最全 | 深度长文 | 真实情绪 | **趋势与客观数字** |
| 盲区 | 只有公司级 | 校招偏多 | 噪声大 | 没有体验感 |

**组合用法**：脉脉给「给多少钱、干多久」，职友集给「还在招人吗、招的人什么水平」。两者交叉能识别「高薪但正在收缩」的陷阱——这正是携程金融的情况。
